## 1. Codex model retirement today — TEST NOW

**What changed.** OpenAI states that GPT-5.4 and GPT-5.4 mini stop being available in Codex through ChatGPT sign-in on **31 August 2026**. The documented replacements are GPT-5.6 Terra and GPT-5.6 Luna. API-key use is not affected.

Primary source: [Using Codex with your ChatGPT plan](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)

**Why it matters.** A saved model default can turn a healthy WijSAmen task into an avoidable failure. Repository search found no literal `GPT-5.4` reference, so no GitHub edit is needed.

**Maturity/access.** Effective today for ChatGPT-authenticated Codex. The present agent environment already exposes GPT-5.6 models, but every saved external task/configuration was not independently inspected.

**Small reversible test.** On the next normal run of each existing task, verify that it starts and that any visible model selector/default is not GPT-5.4. Do not recreate working tasks. Success: normal start plus durable output/readback. Failure: model-unavailable error; rollback is selecting Terra for ordinary work or Luna for low-cost work, preserving the prompt and durable state.

## 2. Portable Agent Plugins 1.0 — TEST NOW, bounded

**What changed.** Agent Plugins 1.0 became generally available across VS Code, Copilot CLI, the Copilot app and SDK. The open package can carry skills plus MCP configuration, with client-specific behavior namespaced separately.

Primary source: [Agent Plugins 1.0](https://github.blog/changelog/2026-08-12-agent-plugins-1-0-in-vs-code-copilot-cli-and-the-copilot-app/)

**Why it matters.** WijSAmen currently depends on instructions repeated across task prompts and tools. One portable, versioned continuity/evidence skill could reduce drift between GitHub, Codex and later local agents without copying the whole private corpus.

**Maturity/access.** The specification and Copilot support are GA. Installation in Remco's exact ChatGPT Plus/Codex surface and Android workflow remains unverified. A plugin may include executable MCP components, so permissions and source review remain mandatory.

**Small reversible test.** Package only the five-axis Evidence Passport schema and readback rule—no secrets, autonomous messaging or write permission—as a minimal plugin fixture. Validate its manifest locally and compare one synthetic audit with and without it. Success: same evidence labels and readback discipline in two supported clients with no extra correction. Rollback: remove the fixture; canonical instructions stay in Drive/GitHub.

## 3. Copilot CLI recovery and permission defaults — WATCH for Android support

**What changed.** GitHub's 28 August release adds recovery of sessions interrupted mid-turn, persistent default execution/permission modes, easier plugin/MCP/skill management and a native Rust runtime.

Primary source: [GitHub Copilot weekly releases — August 24](https://github.blog/changelog/2026-08-28-github-copilot-weekly-releases-august-24/)

**Why it matters.** Interrupted-turn recovery directly addresses WijSAmen's continuity problem, while explicit permission defaults fit the least-privilege protocol.

**Maturity/access.** Released in Copilot CLI, but official Android/Termux ARM64 support and Remco's Copilot entitlement were not verified. A faster Rust runtime does not by itself establish Android compatibility.

**Small reversible test.** Do not install blindly on the phone. First verify an official Android ARM64 asset/support statement. If supported, run a disposable repository session, interrupt it once, restore it and confirm no unrelated file changed. Success: exact session restoration plus clean git diff. Rollback: uninstall the CLI and retain existing GitHub/Drive continuity.

## 4. llama.cpp begins semantic releases — WATCH, then pin

**What changed.** The llama.cpp maintainers introduced a semantic-version release line; `v0.1.2` was still marked pre-release on 18 August while automatic `bNNNN` nightlies continued independently.

Primary sources: [llama.cpp release/versioning discussion](https://github.com/ggml-org/llama.cpp/discussions/27340), [ggml project versioning policy](https://github.com/ggml-org/ggml/discussions/1579)

**Why it matters.** Stable, pinned versions would make future phone/local-model experiments reproducible and recoverable instead of silently changing with frequent nightlies.

**Maturity/access.** Pre-release/WIP at the checked boundary. Termux build cost, memory limits and Android packaging remain device-specific.

**Small reversible test.** Wait for the first non-prerelease tag, then build or install that exact tag in an isolated Termux prefix and record source tag, commit, binary hash, model hash, RAM and thermal result. Success: repeatable golden prompt output after reinstall. Rollback: remove the isolated prefix; do not replace a working runtime.
